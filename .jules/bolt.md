## 2024-05-24 - Redundant sorting of grouped time-series data
**Learning:** The UI rendering logic (`windowRows`) re-sorted historical sparkline points by time after grouping them by window size. However, since the underlying `HistoryStore` already guarantees the input array is sorted by time, iterating and appending to group arrays preserves this chronological order naturally. The secondary sort was an unnecessary O(N log N) operation per render per provider. Also, `Severity.worst()` iterates all windows to find the maximum severity, but once `.critical` is reached, it cannot get any worse, so we can short-circuit.
**Action:** Trust the data source guarantees for ordering. When grouping already-sorted arrays, rely on the preserved insertion order to avoid redundant sorts. For maximum bounds checking (like severity levels), always add early returns when the maximum possible bound is reached.
